# CIM projection field decisions

This is the field profile of the deterministic seed-42 fixture in `tests/fixtures/cim-story-42/`. "Core" means required by this fixture profile because it is present on every row of that dataset; it is not a promise that every future source will observe the field. "Conditional" fields are optional and appear only when the source supports them. The notes identify derived or normalized fields. All projected rows contain `time`, `synthetic`, `sec_data_source`, and `sec_data_cim_dataset`. The installed CIM 8.7.0 definitions for these twelve datasets mark no field as `required=true`; their membership constraints use tags. The project add-on supplies those tags at search time.

| Dataset | Core fields in fixture | Conditional fields and derived values |
| --- | --- | --- |
| `Alerts.Alerts` | `id`, `signature`, `signature_id`, `severity`, `description`, `app`, `event_id` | `description` repeats the detector title; `app` identifies the project detector. Alert evidence remains in the source case bundle. |
| `Authentication.Authentication` | `user`, `dest`, `action` | `src`, `reason`, `session_id`, `src_nt_domain`, `signature_id`, `app`, `event_id` depend on web or Windows source. Windows event codes become `success` or `failure`. |
| `Change.All_Changes` | `user`, `src_user`, `dest`, `object`, `action`, `signature_id`, `event_id` | The Windows group-add event sets project metadata `sec_data_cim_subdataset=Account_Management` and `action=modified`. |
| `Data_Access.Data_Access` | `user`, `dest`, `object`, `object_path`, `object_category`, `action`, `access_result`, `signature_id`, `event_id` | `src` and `process` depend on audit event type. `object` is the path basename; share-relative targets are joined with the observed local share path. Windows 4663 records have `action=read` and `access_result=success`. A 5145 share access check has `action=unknown`, with its audited success/failure in `access_result`; the observed requested access and reason appear in `requested_action` and `access_reason` where available. These three access-context fields are outside the CIM model result set. |
| `Endpoint.Filesystem` | `dest`, `user`, `file_path`, `process`, `action`, `event_id` | Sysmon event code 11 is mapped to `created`. |
| `Endpoint.Processes` | `dest`, `user`, `process`, `process_id`, `event_id` | `action`, `dvc`, parent process identifiers, GUID, and command line depend on source. Recon observations do not assert an action. Sysmon codes 1 and 5 map to `created` and `terminated`. |
| `Endpoint.Registry` | `dest`, `user`, `process`, `registry_path`, `registry_value_data`, `action`, `event_id` | Sysmon event code 13 maps to `modified`. |
| `Network_Resolution.DNS` | `src`, `dest`, ports, `query`, `query_type`, `record_type`, `transaction_id`, `transport`, `query_count`, `answer_count`, `message_type` | `answer`, `ttl`, `reply_code`, `reply_code_id`, `response_time`, `session_id`, `dvc`, and `event_id` depend on observed query/response details. `answer` and `ttl` remain multivalue; the add-on maps Splunk's JSON `answer{}` and `ttl{}` fields to their CIM names. Response time converts milliseconds to seconds for recon output. |
| `Network_Traffic.All_Traffic` | `src`, `dest`, `dest_port`, `transport` | `action`, `bytes`, directional bytes, packets, duration, `rule`, `app`, `dvc`, and session details depend on source. Zeek originator/respondent IP bytes map to outbound/inbound bytes; byte totals add observed directions. Recon duration converts milliseconds to seconds. No action is invented for Zeek conn or ambiguous recon outcomes. |

These links and `action` support direct-event investigation but are not fields in the CIM ticket model's result set. The source case actions retain narrative and evidence references. |
| `Vulnerabilities.Vulnerabilities` | `dest`, `dest_ip`, `dest_port`, `signature`, `signature_id`, `severity`, `cvss`, `status`, `category`, `vendor_product`, `asset_id`, `finding_id`, `description`, `transport` | `cve` is emitted only when the observed identifier is a CVE. `info` normalizes to `informational`; the assessment timestamp is the observation time. Several source context fields remain outside the CIM model result set. |
| `Web.Web` | `src`, `dest`, `dest_port`, `url`, `http_method`, `status`, `bytes_out` | `bytes_in`, `action`, `dvc`, `session_id`, and `src_port` depend on source. URLs preserve host plus URI without inventing a scheme. |

## Unsupported and out-of-model observations

The four recon `service_query` observations and one web `account_locked` observation in the seed-42 source bundle have no sound mapping in this projection. Inventory, entities, identities, policies, compliance snapshots, scenario truth, and raw vendor events remain separate. The projection does not assert packet payloads, the contents of an uploaded file, or actor continuity between the public probe and later operator activity.

Some retained fields are valuable in direct event searches but are not selected by the CIM model result set, including `Ticket_Management.action`, `Network_Traffic.probe_type`, and source-specific correlation identifiers. Use raw `index=... sourcetype=secdata:cim:json` searches when those fields are needed. The [lab report](splunk-validation.md) records live extraction and membership checks; model membership is not a complete semantic audit of every optional field.
