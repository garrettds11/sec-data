# Linked ingress fixture

The story bundle renders selected recon interactions from separate edge and application perspectives. `ingress-firewall.jsonl` and `edge-proxy.jsonl` are project-owned field projections. `ingress-zeek-conn.jsonl`, `ingress-zeek-http.jsonl`, and `ingress-zeek-ssl.jsonl` use documented Zeek JSON field names. `ingress-truth.json` carries the cross-sensor interaction links and belongs outside analyst-facing indexes. The original `recon.jsonl` remains the normalized source stream.

The selected public sequence includes a connected HTTP request for `/.env`, an HTTPS request for `/`, and a blocked probe to an unpublished port. A separate internal request for `/` is ordinary browsing. Public firewall rows show the public destination and, for allowed traffic, the private address after NAT. The blocked probe has no translated flow, proxy observation, or application request. The Zeek sensor is modeled behind the NAT: its responder address is private. `collected_at` is later than occurrence time on firewall and proxy rows. The firewall byte counts represent the completed request, while the earlier normalized recon connection fields are a decision-time snapshot. The two sources therefore need not have the same counters.

The [Zeek connection log](https://docs.zeek.org/en/current/reference/logs/conn.html) carries network endpoints, service, UID, and byte counts. The [Zeek SSL log](https://docs.zeek.org/en/current/reference/logs/ssl.html) carries TLS metadata; it cannot reveal an encrypted HTTP path. This fixture emits a Zeek HTTP row only for cleartext port 80. The terminating edge proxy and application can record the path for HTTPS. The `sensitive-path` WAF rule logs the `/.env` request; it does not confirm compromise or block it.

## Splunk smoke test

[TA for Zeek](https://splunkbase.splunk.com/app/5466/) **1.0.11** is the pinned candidate for the Zeek JSON streams. A copy retrieved through [Splunk's Attack Range binary manifest](https://github.com/splunk/security_content/blob/develop/contentctl.yml) was inspected locally (SHA-256 `d5fabacc1cae4c66b19b633d165687f11e10772c1d734746e674e2ee9f7fdcfc`); it is not distributed with this repository. The edge firewall/proxy projections have no claimed vendor add-on. Their ingestion and CIM mappings must be authored separately if used in Splunk.

In a test Splunk instance with the pinned add-on and CIM, ingest the three Zeek files as `zeek:conn`, `zeek:http`, and `zeek:ssl`. Check `ts` to `_time`, UID, dotted address fields, ports, byte direction, HTTP status and path, and TLS server name. Verify Network Traffic and Web event types, tags, and data model inclusion; assess TLS model support separately. For the project-owned edge sources, inspect the raw `action`, public and translated destination, `uri`, status, and `collected_at` fields before considering Network Traffic, Web, or Intrusion Detection mappings. **No live Splunk ingest or CIM membership has been verified.**
